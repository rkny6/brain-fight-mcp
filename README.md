# Angel & Devil MCP (v0.1)

A local, zero-cost MCP server that stages theatrical **Angel vs. Devil** inner-conflict
debates for a Client LLM (Claude, Cursor, etc.) to perform. No external AI API calls —
all positions, reasoning, and relationship dynamics are generated by deterministic
rule engines and a local SQLite database.

## Why

Ask "should I quit my job?" and get back an Angel arguing caution and a Devil arguing
boldness — with their own evolving relationship (respect, annoyance, cooperation) that
changes conflict to conflict, occasionally swapping roles for a "wait, what?" moment.

## Install & Run

```bash
npm install
npm run build
npm start
```

Or run directly via `npx` once published:

```bash
npx angel-devil-mcp
```

### Add to an MCP client (e.g. Claude Desktop / Claude Code)

```json
{
  "mcpServers": {
    "angel-devil": {
      "command": "npx",
      "args": ["angel-devil-mcp"]
    }
  }
}
```

For local development, point `command`/`args` at `node` and `dist/index.js` instead.

### Database location

State is stored in a local SQLite file at `~/.angel-devil-mcp/state.sqlite3`.
Override with the `ANGEL_DEVIL_DB_PATH` environment variable (useful for tests or
running multiple isolated instances).

## Tools

| Tool | Purpose |
| --- | --- |
| `summon_angel` | Angel's solo perspective on a situation (no conflict). |
| `summon_devil` | Devil's solo perspective on a situation (no conflict). |
| `start_inner_conflict` | **Main tool.** Runs a full Angel vs. Devil debate, updates their relationship, returns `performance_instructions`. |
| `get_relationship` | Current relationship state + recent conflict history for a session. |
| `reset_relationship` | Wipes state for a session. Requires `confirm: true`. |

All tools accept an optional `sessionId` (defaults to `"default"`) so different
projects/users don't share state.

## Resources

- `angel://profile` — static Angel personality profile
- `devil://profile` — static Devil personality profile
- `relationship://state` — live relationship state for the default session
- `relationship://state/{sessionId}` — live relationship state for a specific session

## How the "Hot Take" engine works

1. **Topic matching** — `context`/`topic` text is scanned for keywords (e.g. "quit job",
   "buy", "apologize") against a template table; falls back to a generic
   Safety-vs-Freedom debate if nothing matches.
2. **Intensity scaling** — `low` / `medium` / `high` map to extremity multipliers
   (0.3 / 0.6 / 0.9) that control how dramatic the phrasing and reasoning are.
3. **Relationship bias** — high `angelRespect` makes Angel more accommodating; high
   `devilAnnoyance` makes Devil purely contrarian, opposing whatever Angel says.
4. **Role reversal** — if `cooperation > 0.7`, there's a 15% chance Angel and Devil
   swap archetypes for that one conflict, flagged via `isRoleReversal: true`.

## Relationship update rules (after each conflict)

- Angel wins → `angelRespect += 0.02`, `devilAnnoyance += 0.03`
- Devil wins → `devilRespect += 0.02`, `angelAnnoyance += 0.03`
- Draw → `cooperation += 0.05`
- Role reversal occurred → `cooperation += 0.02` (stacks with the above)

All values are clamped to `[0, 1]`.

## Design notes

- **No LLM calls, no auth, no cloud** — everything runs locally against SQLite.
  Cost is $0 and there's nothing to leak.
- **`performance_instructions`** is the field that matters most for output quality:
  it tells the calling Client LLM *how* to voice the debate (tone, pacing,
  absurdity) so the structured JSON becomes lively dialogue instead of a dry
  summary.
- Comedy over accuracy: Devil isn't always wrong, Angel isn't always right.
